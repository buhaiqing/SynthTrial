# SynthTrial · Self-Review Playbook (anti-recurrence log)

> Required by `AGENTS.md` §7.1 and DCL-4: every `[BLOCKER]`/`[MAJOR]` fixed in a
> review round is appended here as a `症状 / 根因 / 修法 / 边界` row, so the same
> class of defect cannot come back unnoticed.
>
> **Every row below is a defect this repository actually hit** (row 11 is one that is
> still live in the prose). Sources are the
> commit bodies (`git show <sha>`) and the code/tests that now guard them — no
> invented incidents. Reproduce any row with the command in its Evidence cell.
>
> Standing lesson that cuts across all rows: a green suite proves nothing about a
> property the suite cannot observe (a subprocess-level property, a degenerate
> input, an assertion that happens to be vacuous). Fix the guard, not just the bug.

## How to add a row

1. Trigger: a `[BLOCKER]`/`[MAJOR]` fixed during GCL, a reproduced production
   defect, or a user-reported wrong number.
2. Fill all four columns. The **边界** column is the one that stops recurrence-fix
   theatre: state where the fix does *not* apply and what the guard cannot see.
3. Cite a commit sha and a guard (test id, or an exact command) in 证据. A row
   without a guard is a note, not a playbook entry — add the guard first.
4. Deduplicate by root cause, not by symptom: two symptoms with one cause are one row.
