## 3. Go ↔ Python contract (single source of truth)

- Buf proto as canonical schema (one proto dir `./proto/`). All Python Pydantic + Go structs regenerate from it (`starlette-fastapi gen`, `buf generate`).
- Python ↔ ClickHouse uses Apache **Arrow Flight** (not `client.execute`) to lift rows by batches & avoid row-packing overhead.
- Go ↔ Python transport: **mTLS gRPC** over Kubernetes internal (service-mesh) only.
- Shared environment vars: `TASK_ID`, `CONFIG_HASH`, `APPROVAL_TOKEN` injected through Prefect; none of them from user input.

---

## 4. Dual-hybrid working rule

1. **Identity boundary** Go only at boundary/QPS; Python at semantic/business data layer.
2. **Config truth**: All environment data in `config/app CONFIG.yaml` (no hard-coded URLs; connection env generated by helm chart at deploy).
3. **Trace**: Langfuse/OpenTelemetry unified trace_id pass from Go→Python via `metadata.traceparent`.
4. **No-duplicate-expression**: All arithmetic live only in `st-infer` output; Go ledger reaps what it receives never recomputes.
5. **Immutability**: Task ID `T-YYYYMMDD-HHMMSS-rand4` -> `immutable batch`. Re-run always new task with same content hash, never overwrite.

## 5. Data flow narrative (single task, offline)

1. `POST /tasks` (UI or CLI) → `st-gateway`, writes row (audit) to Postgres (immutable).
2. Prefect picks `eval_offline` Flow; binds a runner pod `Py 3.12`.
3. Runner loads config (model version, dataset version SHA, param hash), claims data shards (by date/site) via Arrow/CH.
4. For every model variant (A,B), inference → telemetry shards (immutable; full text) → out to S3.
5. `st-infer` compute paired stats; `st-safety` execute H-row set; report draft stored to PostgreSQL + S3.
6. `st-ledger` emits metrics aggregation in 5m window.
7. Task status into complete; DLQ is separate.
8. User reads report via UI (Render) or CLI `stctl reports list`.

## 11. Go+Python interface contract and schema flow


### 11.1 Use protobuf registry `!sch` as single contract

- Every request body `(task, shard)` serializes to `TaskConfig`/`ShardTask` Protobuf; diagrams referenced in §9.
- `st-infer` gRPC service returns `ReportDraft` with `reproducibility_hash` (hex).
- `st-safety` gRPC returns `SafetyVerdict` with `{blocker_count, warning_count, pi_targets}`.

### 11.2 Prefect driver pattern

- Called both from `st-gateway` (Go Path: delegating to Prefect API) and `st-registry`.
- Handles retries `retry_on={TransientError}`, idempotent.

### 11.3 Replay audit policy

- Immutable task always produces `TaskAudit { change_gap, parent_task, hash }`, auditable signed by Go middleware using content address.
