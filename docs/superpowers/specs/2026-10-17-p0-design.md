# SynthTrial P0 — Offline Evaluation Core · Design Spec

> Date: 2026-10-17
> Status: Approved by goal (slightly adapted from docs/design.md)
> Scope: P0 only (offline evaluation + governance + paired stats + safety + report)
> Out of scope: online A/B infra (st-bucket/P1), causal inference (st-causal/P2)
> Implementation plan: [`../plans/2026-10-17-p0.md`](../plans/2026-10-17-p0.md)

## 1. Problem Statement

Algorithm engineers submit a candidate model version; the system runs an immutable, reproducible offline evaluation against the same sample set as the baseline model, and produces a decision-ready report (safety verdict + paired statistical conclusion + audit trail). Today these tasks are ad hoc; the platform turns them into a versioned, testable artifact chain.

## 2. Solution

A Python-first monolith (Type A MVP per design.md §10.2) with first-class spec/plan/TDD. Core packages under `src/st_platform/`:

- `registry` — metric definitions, versioned, referenced by ID (st-ledger)
- `dataset` — immutable datasets, split, annotation stats, contamination detection
- `task` — immutable task lifecycle, Prefect-less single-process DAG with retry
- `infer` — paired statistics (t, Wilcoxon, McNemar), CUPED, multiple correction
- `safety` — pluggable redline checks with 3-tier verdict
- `report` — Jinja/LaTeX rendering + immutable audit ledger
- `audit` — append-only audit events with hash-linked parent
- `cli` — `stctl` CLI exposing task submit → report retrieve

Storage: PostgreSQL/SQLite (production/dev); CH not required in P0; JSON artifact output.

## 3. User Stories (condensed)

- As an algorithm engineer, I submit a candidate model tagged `v2` against dataset `cards-1.0`, get report within <4h, know if it can be promoted.
- As an evaluator, I verify every report number maps to registry ID + version.
- As compliance, I see a 3-tier safety verdict with evidence paths.

## 4. Implementation Decisions (modules & contracts)

- Package `src/st_platform/common` holds pure domain models (Pydantic v2) & hashing.
- Each module exposes a service interface `*Service` + repository interface `*Repo` for DI.
- Immutable `Task.id` content-addressed `sha256(config JSON | dataset sha | code sha)` so identical inputs replay.
- Dataset contamination: exact SHA and case-signature based on `(case_id, text_hash)`.
- **An unchecked contamination claim is not a clean claim** — see §4a.
- Paired stats require two arrays aligned by `case_id`; raise `UnalignedCases` instead of silent drop.
- Multiple correction forced any time `len(metrics) × len(subgroups) > 1`.
- Report stores JSON source of truth + HTML view; PDF left to P1 (Jinja HTML enough + MD fallback).

## 4a. Unknown contamination fails closed (T-M7-11)

**Problem.** `contamination_detect(eval_ds, train_sigs)` cannot tell an *empty* training
corpus from an *absent* one. `EvaluationPipeline.run(train_signatures=None)` therefore
manufactured a conclusion it never measured. Reproduced end-to-end on `main`:
`stctl run` with no `--train-signatures` emitted
`train_overlap_count=0, contaminated=False` and `promotable: true`.

That is the offline twin of design.md §3.2 (「不可见 ≠ 未曝光」): an eval score means
nothing while a train/eval overlap is unexcluded, and CP-7's named anti-pattern of
recording 「没采到」 as `0`.

**Contract.**

| Input | `train_corpus_supplied` | `contaminated` | counts / ratio / signatures |
|---|---|---|---|
| `None` (never supplied) | `False` | `None` | `None` (unknown, **not** `0`) |
| any iterable, incl. `[]` (supplied) | `True` | measured bool | measured |

- `contamination_violated(contamination)` is the single reader of that shape and returns
  **True for unknown** — fail closed, mirroring the existing precedents: an unevaluated
  redline (`safety_verdict`) and an unregistered rule id (`SafetyChecker`) are both
  BLOCK, never PASS. It lives in `dataset.core` because that module owns the shape.
- Consequence: a run without a training corpus still produces its effectiveness numbers,
  but its verdict is `BLOCK` and `promotable is False`. Losing the evidence to an exception
  would be worse than losing the promotion.

**Out of scope:** teaching anyone to *produce* training signatures — that is the P1 corpus
plumbing. P0 only has to stop certifying a check that never ran.

## 4b. The audit ledger must be on the real path and durable (T-M7-12)

**Problem.** `AuditLedger` had exactly one caller: `cmd_demo`. `cmd_run` — the path
T-M7-01 wired — wrote **zero** audit events, so the ledger named in design.md §4.1 was
decoration on a synthetic demo. Worse, the ledger was in-memory only: `append` grew a
list and `export()` returned it, so even the demo's chain vanished when the process
exited. Nothing about a real evaluation was recoverable as evidence.

**Contract.**

| Item | Rule |
|---|---|
| Persistence | `AuditLedger(path=...)` appends one JSON line per event to an **append-only JSONL** file. `.jsonl`, not `.json` — `ReportStore.list_hashes()` globs `*.json`, so a `.json` audit file would be listed as a report. |
| Chain across restarts | Opening an existing file reads the tail hash and continues the chain from it, so the chain is verifiable across processes, not just within one. |
| Report integrity | Audit entries carry `created_at`; that timestamp must **never** reach `report_hash`, or identical inputs would stop reproducing (design §4.1). |
| Event ownership | Task lifecycle (`task.submitted` / `task.completed` / `task.failed`) belongs to the CLI, which owns the state machine; `evaluation.completed` belongs to the pipeline, which owns the verdict. |
| Tamper evidence | Reopening a ledger whose file was edited mid-chain must fail `verify()`, not silently re-link. |

**Out of scope:** signing, external timestamping, multi-writer locking. A single-process
append-only file is what P0 can honestly claim.

## 5. Testing Decisions

- TDD: write red tests first using `pytest`; `pytest -v`.
- Tests pass **real** code paths; no monkey-patch of core classes (parallel-guard clause).
- Mutation-safety: tests target behavior, not exact wording unless API contract.
- Property test for paired-array alignment uses `hypothesis`.
- `pytest coverage` ≥ 80% on non-I/O logic.

## 6. Out of Scope (P0)

- Online A/B (P1), causal inference (P2), positive worst-case latency estimation.
- Multi-tenant SaaS auth beyond simple RBAC seeded data.

## 7. Further Notes

- Single process scheduler only (Prefect optional P1). SQLite dev / Postgres prod.
- Subagent model uses main model. GCL review per functional change.
